Vanguard Memory Node

Deterministic, content-addressed local memory for AI agents. No cloud. No embeddings. No semantic drift. Your data stays on your machine.

Install from npm View on GitHub
$ npm install -g vanguard-memory-node

Why local memory?

Vector databases and embedding-based memory systems have three fundamental problems. VMN solves all three.

⚡

Embedding drift

Retrieval results change whenever the embedding model updates. The same query returns different results next month than it does today.

☁️

Vendor lock-in

Chroma, Pinecone, Weaviate — all require a running service, an account, and per-query API charges that compound at scale.

🔒

Privacy exposure

Every document you embed leaves your machine. Clinical notes, legal briefs, proprietary code — all uploaded to third-party inference endpoints.

How it works

1

Ingest

Feed any text to vmn_ingest. It is SHA-256 hashed, segmented into 1800-character chunks (paragraph → sentence → word → hard ceiling), and indexed in a sharded BM25 inverted index with 256 posting buckets.

2

Normalize

Every token passes through a deterministic 5-stage pipeline. Phrase aliases substitute multi-word clinical and technical terms before tokenization. A 13-rule suffix stemmer and synonym cluster expansion ensure smoking, smoker, and tobacco use all match the same indexed root.

3

Score

Queries run BM25 (k₁=1.5, b=0.75) against only the posting buckets that contain the query terms — no full index scan. A stemmed-token fallback fires when BM25 scores zero, catching edge cases without producing false positives.

4

Recall

A 900-character evidence window is returned, centered on the highest-density keyword match in the best-scoring chunk. No hallucination — the text is read verbatim from the original object file.

Unicode NFC→normalize accents and composed characters
Phrase aliases→blood pressure → bp, rate limiting → ratelimit
Tokenize→split on whitespace / punctuation, min length 2
Stem (13 rules)→medications → medica, smoking → smok
Stop-word filter→remove articles, prepositions, pronouns
Token alias expand→smok ↔ tobacco ↔ cigarett ↔ nicotine

MCP tools (10)

All tools are exposed over stdio MCP transport, compatible with Claude Desktop, Cursor, and any MCP-capable host.

vmn_ingest

Store text locally as a SHA-256 content-addressed shard. Returns root hash and vault path.

core
vmn_recall

Retrieve a 900-char evidence window from a specific shard using BM25 + stemmed-token scoring.

core
vmn_search

Full-vault keyword search across all ingested objects. Returns ranked results with snippets and scores.

core
vmn_list

List all memory objects with optional namespace filter. Returns title, segment count, and timestamp.

catalog
vmn_inspect

Return full catalog metadata for a specific shard: title, namespace, tags, size, excerpt, timestamps.

catalog
vmn_delete

Permanently remove an object and all its index entries from the local vault.

catalog
vmn_stats

Aggregate vault statistics: entry count, total bytes, namespaces, oldest and newest timestamps.

diagnostics
vmn_index_status

Current BM25 index state: READY, REBUILD_REQUIRED, REBUILDING, or DEGRADED.

diagnostics
vmn_rebuild_index

Rebuild the full index from authoritative object files. Safe at any time — objects are never modified.

maintenance
vmn_sync_vault

Sync a local object to the ExergyNet LNES-17 ledger. Returns Canonical Manifest JSON. Requires EXERGYNET_API_KEY.

bridge

ExergyNet Vault Bridge

New in v1.4.0. Connect your local vault to the LNES-17 thermodynamic ledger for cross-device recall and cryptographic provenance.

vmn_sync_vault

  • Reads the raw authoritative object file from ~/.vanguard/local_vault/<hash>.txt
  • POSTs to EXERGYNET_VAULT_URL/api/xlmp/ingest with Authorization: Bearer <key>
  • Returns the server's Canonical Manifest JSON to the agent
  • Safe no-op when EXERGYNET_API_KEY is absent — never crashes the local node

Vault layout

All data lives under ~/.vanguard/. The index is derived state — delete it anytime and vmn_rebuild_index regenerates it from the authoritative .txt objects.

~/.vanguard/
├── local_vault/
│   └── <sha256>.txt          # authoritative objects (never modified after write)
├── catalog/
│   └── <sha256>.json         # per-object metadata (O(1) reads)
├── segments/
│   └── <sha256>.json         # segment records + term frequencies
└── index/
    └── v2/
        ├── index_manifest.json   # version + state
        ├── corpus_stats.json     # BM25 corpus statistics
        └── postings/
            └── <2-hex>.json  # 256 sharded posting buckets
